Walkthrough & Demo

CREV Inspector v0.7

A Chrome side-panel extension for working with Corporater BMP the way developers want to, not the way the stock UI allows. It overlays every widget with its real identity and adds object inspection, code editors, Blueprint, CVO tooling, and optional AI, with no round-trip through Configuration Studio.

What it is

BMP's web portal shows you a rendered scorecard but hides the configuration underneath: object IDs, types, the Extended Code behind a widget, how tabs and containers nest. To change anything you normally open Configuration Studio, hunt for the object, and reload.

CREV Inspector collapses that loop. It runs as a Chrome side panel next to the live BMP page. Every widget gets a coloured pill with its real ID; click it and you drop straight into the thing you wanted: a property editor, the Extended Code editor, or the layout reorder tool. Changes are written back to BMP through Extended Code.

Who it's for: developers and configurators building or debugging BMP scorecards who want to see structure and edit logic in place, without the Config Studio context switch.

Install

  1. Download the latest crev-inspector-x.y.z.zip from the Releases page and unzip it.
  2. Open chrome://extensions/ and turn on Developer mode (top-right).
  3. Click Load unpacked and select the unzipped folder.
  4. Pin the extension to the toolbar so the side panel is one click away.

It is an unpacked developer extension (not on the Chrome Web Store), so it updates by downloading a new zip. The Connect tab shows a banner when a newer release is available.

First run: connect a profile

  1. Open the side panel and go to the Connect tab.
  2. Add a server profile with the BMP base URL. Username and password are optional when you are already logged into BMP in the browser.
  3. Approve Chrome's site-access prompt for that server. Profiles auto-switch based on the BMP URL prefix, so one browser can drive several environments.
Session-first authentication. CREV borrows your existing BMP session and mints its own short-lived token. If you add credentials, they are an automatic fallback and are AES-GCM encrypted at rest. An http:// profile URL raises an inline warning.

How it works in the background

Three pieces cooperate, and the side panel never talks to BMP directly:

BMP page (content script) → Service worker → BMP server (binary commands + EC) → Side panel UI
  • Content script (isolated world). Injected into the BMP page, it detects whether the page is BMP, scans the DOM for objects that carry a real ID (data-rid attributes and ?rid= / ?tabrid= links), and paints the type-pill overlay. It also reads which tab is currently selected and can scroll-and-highlight a widget on request.
  • Service worker. The brain. It owns session-first authentication, routes messages between the page and panel, caches object identities, and batches enrichment so pills can show names and types instead of bare numbers.
  • Binary commands and Extended Code. CREV uses BMP's Configuration Studio command protocol plus Extended Code for the operations each handles best. EC reads run as non-transactional previews; writes require an explicit save, execute, or Blueprint Apply.
  • Per-window state. Inspect mode, the active profile, and panel routing are tracked per browser window, so inspecting in one window never paints pills onto another.
RIDs are 64-bit. BMP object IDs exceed JavaScript's safe integer range, so CREV handles them as strings everywhere. The friendlier businessId (e.g. sc_risk_register) is what you usually copy and reference.

Features

PILL Type-pill overlay

Every widget on the BMP page gets a coloured ID badge.

The colour encodes the object type (green for scorecards, indigo for layout tabs/containers, red for tables/visualisations, blue for inputs, purple for logic). Interactions:

  • Click a pill to open the object in the side panel.
  • Double-click for a quick inspector popover.
  • Right-click to set that object as the working context.
  • Alt-click copies the RID, Shift-click the template business ID, Ctrl-click a t.someBid reference.

OBJ Object inspector

A type-aware detail view for any object.

Shows identity, references, siblings, code fields, access, and the flow chain for inputs and actions. From there you can jump directly into the correct code editor, CVO studio, Blueprint location, or source object.

EC Extended Code editor

A floating CodeMirror workbench for any EC-bearing property.

  • Preview (Ctrl/Cmd+Enter) dry-runs safely; Execute commits.
  • Run history and an output panel keep your last results.
  • Vars + Properties panel infers the type of every _v := SELECT X and lets you click any property to insert its accessor at the cursor.
  • Hover docs, inline runtime-error markers, and syntax help are built in.

BP Blueprint

Edit page structure and appearance directly over the live portal.

Blueprint renders the page as an editable grid of tabs, containers, widgets, and supported input/action flows. Drag to move, swap, reorder, and resize; add or rename elements; switch to Style for colours, visibility, borders, and paintbrush presets. Every change is staged with undo/redo. Apply first shows the generated plan and blast radius, then commits only after confirmation.

CVO CVO + text studio

Author HTML and JavaScript with a live, isolated preview.

Edit CVO source side by side, load real render data and hosted resources into the sandbox, manage CVO inputs, and re-read the saved properties from BMP to catch sanitization or silent rollback. TextElement mode uses the same studio and adopts BMP's stored, sanitized result.

AI Optional AI assistant

Workspace-grounded chat and code edits, using your own provider key.

Configure Anthropic, OpenAI, DeepSeek, or Grok to add an AI tab plus inline assistance in the code editors. It can inspect selected objects and layouts through read tools, preview proposed EC, and hand edits back to the active editor. With no key configured, none of the AI controls render.

DIF Diff & compare

See exactly which properties differ between two objects.

Pick any two objects — RID vs RID, instance vs template, or by ns.bid reference — and get a side-by-side property comparison. Useful for "why does this instance behave differently from its template" or comparing the same object across environments.

SR Code search

Full-text search across all Extended Code in the workspace.

Indexes the expression bodies of every code-bearing object (expressions, tables, methods, field logic, action buttons, create views) so you can find where a function, a RID, or a snippet is used. Results link straight to the object.

ENV Multi-window & profiles

Per-window inspect state and per-server profiles.

Each Chrome window has its own inspect toggle and panel. Profiles bind to a BMP URL prefix and auto-switch, so moving between sandbox, dev, and production just works and the right credentials and cache are used for each.

A typical session

  1. Open a BMP scorecard. CREV detects the page and paints type pills on every widget.
  2. Open the side panel (Ctrl+Shift+Y). The Inspect tab auto-detects the scorecard and lists its visible widgets.
  3. Spot a table that's misbehaving. Click its pill → the object inspector opens with its properties and code fields.
  4. Open the Extended Code editor on the table's expression, tweak it, Preview to dry-run, then save the property. Use Blueprint for layout or style changes and inspect its impact preview before Apply.
