Flow hierarchy — compact & role-differentiated

Same data, but the different kinds of element now look different instead of all being 3-letter tags: the widget is a title, the container is a faint context line, the type is a small color dot, the key is a mono identifier with a key glyph, and code is a code glyph in purple (so "has logic" jumps out). No more =.

V1 · One line per field
Tightest. Type = color dot, name, then key (mono + key glyph) and code (code glyph + lines) right-aligned. Differentiation is by glyph + color + font, not by boxing everything.
V2 · Name first, behavior below
Names get the full width on line one; the quiet second line carries key + code only when present, so fields with logic visibly stand out from plain ones. A touch taller, very scannable.
